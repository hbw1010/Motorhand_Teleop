# Wuji / Sharpa 并列遥操与反馈设计

## 已确认的目标

用户要求在当前 Motorhand 项目中增加 Sharpa，与 Wuji 并列提供仿真遥操、真机遥操力反馈、轨迹回放与人手接管。两台真机已接入现场。用户进一步明确：设备控制代码并列组织；设备特异行为允许分别实现；Sharpa 首版使用 SDK 关节力矩，**不使用触觉**。

本轮基线是 `sim2.0` 的 `8e34ca4`。用户提供的 Sharpa 资产位于 `Motorhand_FFB/assets/sharpa-hand/`。独立开发工作区为 `/home/boen/.codex/worktrees/172f/Motorhand_Teleop_transfer`，分支 `feat/sharpa-parallel-control`；原工作区和已保存版本保留。

## 已核实的输入

- 左右手各22个转动关节和22个位置执行器，单侧 MuJoCo 模型可加载、步进且状态有限；原模型步长0.002秒。
- 本机有用户已有的 Sharpa Wave SDK 5.0.11 完整资源包，包含C++头文件、`libsharpa-wave-sdk.so`和官方示例。使用该版本，不混用另一ABI的Wrapper库。
- SDK `State`包含`angles`、`velocities`、`torques`、设备时间、序号和`system_clock`主机收包时间；`set_joint_position`使用rad，MIT前馈接口使用Nm。`torques`按SDK报告的关节力矩通道保存，不称为已标定净接触力。
- SDK `set_control_mode`会隐式使能，必须留在明确的使能流程内，不能用于只读连接。
- 只读发现已经识别到一只Sharpa右手、型号WaveSE-R-01、固件3.0.10；实际SN由本地设备配置或CLI显式传入，不在日志记录内网地址。Wuji本轮扫描为空，后续独立排查，不能用另一设备代替。
- 相邻工程已有Sharpa数值模型和生命周期适配可供理解，但本工程运行时不能导入相邻工程、ROS或依赖其绝对路径。
- 用户明确指定`/home/boen/hand/dex_glove/real_hand`作为Sharpa控制接口参考。以其中`hands/sharpa_hand.py`的设备身份、源时间、控制权、故障锁存和自身连接释放语义为基准，再适配本项目C++共同控制接口。

## 架构决定

采用用户选择的“并列设备模块＋共同控制层”。不把Sharpa塞入`WujiDevice`、`WujiRetarget`或以Wuji为名的会话类；也不复制一套完整控制状态机分别维护。

拟定职责：

| 模块 | 责任 |
|---|---|
| `native_control/common/` | 具有关节维数和负载类型的状态契约、会话/接管、轨迹、几何工作器、统一手套输出调度 |
| `native_control/hands/wuji/` | Wuji身份、SDK生命周期、20轴模型与重定向、电流A判据和反馈策略 |
| `native_control/hands/sharpa/` | Sharpa身份、SDK生命周期、22轴模型与重定向、SDK力矩判据和反馈策略 |
| `native_control/simulation/` | MuJoCo机械手后端、接触力到关节力矩、离线控制与可视化快照 |
| 既有 Encos / vE3.3 模块 | 12轴手套的标定、闭链、物理轴转换、驱动器阻抗与提交保护 |
| Python入口与查看器 | 参数解析、只读显示、录制浏览；新控制与物理推进使用C++ |

Wuji与Sharpa各自实现完整设备接口，共同层根据明确的型号在创建时选择实现。共同层不使用`if sharpa`解释某个数组的物理单位。20/22关节由类型或描述符明确表达，禁止把22维截断成20维或悄悄补零冒充真实反馈。

迁移现有Wuji模块时保留原命令、配置与已发布接口的兼容包装。兼容层只转换契约或转发，不保留第二份核心控制逻辑。旧Wuji C ABI可保持20轴不变；Sharpa SDK使用自己的C++适配。新共同接口采用各设备的真实维数。

## 数据与设备差异

共同状态至少包含型号、手侧、语义关节名、位置rad、速度rad/s、源收包时间、使能/故障及带来源和单位的负载。缺失负载不能补零伪装成有效观测。

- Wuji：保持当前电流A、偏置、阈值、归一化参考及旧模式语义。
- Sharpa真机：读取SDK关节力矩通道，保留独立偏置、符号、阈值、归一化参考和来源标记；不乘Wuji的Kt、不沿用其A单位阈值。
- Sharpa仿真：由MuJoCo实际接触力在同一姿态下经接触点雅可比形成关节外力矩，转换为约定的负载方向；与SDK报告的负载来源分别标记。位置目标只写执行器ctrl，动力学姿态由`mj_step`推进，不覆盖qpos冒充跟随。

两侧“相同逻辑”指相同的主导方式、位置/反馈解耦、全链路几何投影、单输出所有者、渐入、失效撤力、接管连续性及原始期限。设备的负载估计、参数和能力判据属于各自模块。首版不增加之前尚未实现的`force_reflection`方案，不接入Sharpa触觉或系统辨识模型。

## 重定向和逆向跟随

手套仍使用现场零位/方向/比例，raw degree→模型电机m12→闭链任务点；不能直接把12个电机角按下标拷贝到机械手。

- Wuji继续使用既有官方重定向与20关节定义。
- Sharpa使用自身URDF的22关节FK、解析几何导数、任务点及独立优化器。输入为共同canonical 21点，按手侧选独立模型，不以镜像代替另一侧模型。
- 保持无手套观测的四指MCP侧摆固定零这一现有约定；Sharpa额外拇指/小指自由度通过明确的固定关节或正规项约束，不能声称手套可独立控制22自由度。实际反馈FK保留设备真实自由度。
- 正向输出、逆向影子跟随和力矩投影使用同一设备模型及关节顺序；为Sharpa计算22×12重定向Jacobian及12×22反向投影。
- 接管从真实手套姿态和最后确认的机械手目标平滑接入，保留抓握保持语义，避免接管瞬间自动张手。

## 生命周期与输出

发现/连接/只读状态不使能、不清错、不回零；正式输出要求显式执行、精确SN、手侧和型号/固件校验。Sharpa只释放自己取得的连接和输出权，不调用全局`disconnect_all()`影响其他设备。

Sharpa连接关闭触觉和自动时间同步；SDK原始system_clock收包时间在适配层转换为单调时钟，检查时钟跳变、重复帧、乱序和失效，不能以轮询时刻刷新缓存。设备时间/序号/原始时间一并记录。

Sharpa使能遵循参考实现：通过SDK控制源切换同步实际关节到设备发送器状态，再切换POSITION并确认使能；不先把放松状态裁剪成另一姿态并发送。正常输出在显式回零并确认到位后开放，回零不是改写编码器零点。

共同控制保留100ms原始命令/反馈期限；SDK发生阻塞时也应由独立输出保护处理。缺帧、报警、过期、模式切换撤力，不放宽现有阈值掩盖接入问题。设备增益、限额及单位各自配置，不把Wuji驱动增益直接写入Sharpa。

沿用当前手套现场配置及12轴10 Nm名义上限，原有0.85弹簧预算、G4时间戳修复和回撤修复均须保留。真机联合运动、回零和穿戴测试不属于只读发现；先完成离线与只读验证，再由用户明确启动。

## 入口与兼容性

- 既有`wuji-*`入口继续工作。
- 新增Sharpa独立入口，覆盖发现、仿真、仿真遥操、真机遥操、接触反馈、负载线性反馈、录制、回放及接管。
- 每个入口显式选择一种机械手；“并列”不是默认同时控制两台实体手。两台同时在线时以型号和SN隔离，不让同一手套出现两个输出所有者。
- 共用监视器通过设备描述加载20/22关节、指组和单位。旧Wuji遥测/轨迹保持可读；新轨迹包含型号、手侧、关节顺序和负载单位，拒绝跨型号误回放。

## 依赖与交付

Sharpa模型保留原LICENSE/NOTICE和来源摘要。SDK完整分发放在本项目忽略的`.cache`，由安装脚本从用户给定归档核验版本/摘要后准备，不提交SDK二进制，不依赖其他工程运行时路径。不引入ROS。

实施完成时交付可运行代码、独立配置、启动命令、回归和变更说明。旧Wuji测试必须保留；硬件未实测部分明确说明，不用仅包含空实现的接口宣称真机功能完成。

## 验收

1. 左右Sharpa模型加载、22关节命名/限位/执行器对应、有限步进；同一手套轨迹输出22维且有界，正逆映射和Jacobian形状/符号正确。
2. 两个设备模块可独立构建/选择；共同控制层不依赖另一型号SDK；缺少某SDK只影响该型号真机入口。
3. Sharpa仿真受阻时可通过共同手套链路产生名义反馈，释放时撤力；假手套离线运行无真实串口访问。
4. SDK替身覆盖只读无输出、精确身份、实际收包时间、过期/乱序、模式隐式使能顺序、故障停止与自身连接释放。
5. 同一会话测试覆盖跟随、推理/回放、接管、反向跟随、新鲜度及无扰过渡；Wuji旧入口和旧轨迹回归不变。
6. 监视器/记录支持22关节和Nm来源，不把Sharpa值放进Wuji电流字段；跨设备轨迹拒绝。
7. 运行全套离线测试和构建，再进行现场只读身份/状态核对；不以离线通过代替带人手接触稳定性验证。
